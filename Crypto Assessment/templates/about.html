Assignment Specification
Project Title: Evaluation of Diffie–Hellman Key Exchange and Protection Against Man-in-the-Middle Attacks
Course: Network Security / Cryptography & Information Assurance
Demonstration Focus: Diffie-Hellman Key Exchange, MITM Vulnerability, RSA Digital Signatures, PKI, and Modern TLS 1.3 Architecture
Technical Stack: Python 3.11, Flask 3.0, Cryptography 42.0 (RSA-PSS), HTML5, CSS3, JavaScript (ES6), Bootstrap 5
Database: Zero database dependencies (lightweight, state-free educational runner)
Project Objectives Fulfilled:
  • Normal DH Exchange: Interactive step-by-step modular exponentiation ($g^a \bmod p$, $g^b \bmod p$) with dynamic and custom parameters.
  • Active MITM Attack: Eve intercepting and substituting values ($A_E, B_E$) creating asymmetric secrets ($K_{AE} \neq K_{BE}$) and live message tampering.
  • Attack Detection: Real SHA-256 fingerprint verification comparing expected vs received parameters.
  • Digital Signatures: Genuine RSA-2048 signing with PSS padding and SHA-256 with live tamper invalidation.
  • Protected DH Protocol: Authenticated Diffie-Hellman flow demonstrating that signature mismatches immediately halt key derivation.
  • Evaluation Matrix: Qualitative 7-criteria comparative assessment across 5 architectural paradigms.
  • Architecture Blueprint: TLS 1.3 modern recommended architecture isolating the attacker outside the trust boundary.
Academic Demonstration Disclaimer

This is an academic demonstration tool designed for educational visualization of network security principles, NOT a production security system. Classroom parameters (e.g., $p=23$) are intentionally small for human verification. Real-world systems use at least 2048-bit MODP or 256-bit elliptic curves.

Evaluation Rubric Checklist
Mathematical DH implementation with primality validation
Reproducible MITM substitution showing $K_A \neq K_B$
Real established cryptographic signatures (RSA-PSS)
Interactive tamper detection simulator
Comprehensive 5-approach countermeasure matrix
Responsive cybersecurity UI with zero page reloads needed
