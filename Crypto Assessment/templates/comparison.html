In-Depth Architectural Profiles

1. Basic Diffie–Hellman
Vulnerable
RFC 2631 / Diffie-Hellman 1976

Enables two parties to create a secret over an open wire. Because neither party proves identity, an active attacker on the network path can easily substitute public parameters.

Advantages:
  • No prior trust relationship or PKI needed
  • Minimal computational overhead
Critical Flaws:
  • Completely vulnerable to MITM substitution
  • No entity authentication whatsoever
2. Authenticated DH
Station-to-Station
STS Protocol (Diffie et al., 1992)

Integrates digital signatures inside an encrypted handshake envelope using the newly derived DH key, proving that the entity signing the exchange actually established the key.

Advantages:
  • Eliminates active MITM eavesdropping
  • Provides mutual authentication & Perfect Forward Secrecy
Limitations:
  • Requires trusted public-key distribution
  • Vulnerable to identity misbinding if poorly implemented
3. DH + Digital Signatures
RSA / ECDSA Signing
Signed Parameter Exchange

The initiator and responder cryptographically sign ephemeral DH public shares ($A, B$) using their long-term asymmetric private keys. Any byte modified by Eve fails signature checks.

Advantages:
  • Immediate mathematical tamper detection
  • Cryptographic non-repudiation
Limitations:
  • Requires pre-existing public key verification channel
  • Asymmetric signing introduces latency
4. DH + Digital Certificates / PKI
X.509 Trust Chain
ITU-T X.509 Standard

Solves key distribution at global scale. Public signing keys are wrapped into digitally signed X.509 certificates endorsed by hierarchical Certification Authorities (CAs). Clients verify certificates against trusted root stores.

Advantages:
  • Scales securely to billions of Internet nodes without prior pairwise contact
  • Standardized revocation checking via CRL and OCSP stapling
Limitations:
  • Root CA compromise threatens entire trust domain
  • Certificate expiration and management overhead
5. Modern TLS 1.3 Key Exchange
Gold Standard
IETF RFC 8446

The modern backbone of secure Internet transport (HTTPS). Mandates Ephemeral Diffie-Hellman (ECDHE with X25519 or P-256) combined with X.509 PKI certificate verification. Handshake completes in just 1 round-trip (1-RTT).

Advantages:
  • Guaranteed Perfect Forward Secrecy (ephemeral keys discarded after session)
  • Handshake encryption prevents metadata snooping
  • Eliminated all insecure legacy ciphers (RSA key exchange, SHA-1, RC4 removed)
Limitations:
  • Requires modern cryptographic libraries on both endpoints
